# 採点ログ（生データ）

提出のたびに返ってくる採点サーバーのログ。**この 8 本 × 12 回だけが、この
プロジェクトで唯一の ground truth である。** ローカル評価は退行検知にしか
使えない（§4「信用してよい指標・いけない指標」）ので、ここが失われると
判断の根拠が全部なくなる。`logs/` は `.gitignore` されているため、
こちらへ複製して版管理下に置いてある。

ファイル名は `<採点回>_<構成>_<スコア>.log`。

| ファイル | 構成 | スコア |
|---|---|---|
| `04_smolvla_ens_0.188.log` | SmolVLA + temporal ensembling | 0.188 |
| `05_oft_bare_0.144.log` | OpenVLA-OFT+ 素（本家既定 exec=8） | 0.144 |
| `06_oft_ens_0.293.log` | OFT+ + temporal ensembling | 0.293 |
| `07_tta2_0.304.log` | + TTA 2 視点 | 0.304 |
| `08_tta4_old_0.271.log` | + TTA 4 視点（**旧倍率列・恒等 1.00 混入**） | 0.271 |
| `09_tta2_repeat_0.304.log` | 07 と同一 zip（決定性の確認） | 0.304 |
| `10_h4_0.166.log` | `PARC_ENS_H` 8 → 4 | 0.166 |
| `11_tta3_0.370.log` | + TTA 3 視点（1.00 なし）**最良** | 0.370 |
| `12_grip_tta3_0.370.log` | + 把持の開き直し（ep4 で 2 回発火・救えず） | 0.370 |

回 1〜3 は ensembling 以前で、ログを残していない（スコアのみ PROGRESS.md §1）。

## 使い方

採点結果として返るのは合計スコア 1 個だけだが、`POST /reset` と `POST /act`
を数えれば **8 本それぞれの step 数が復元できる**（300 = 時間切れ = 失敗）。
サーバー自身が出す「前エピソードのレイテンシ」は最後の 1 本を必ず落とすので、
そちらは使わないこと。

```
bash tools/grading_episodes.sh evidence/grading/11_tta3_0.370.log 0.370
```

07 と 09 は同一 zip の再提出で、**step 数まで完全に一致した**。採点は決定的で
測定ノイズはゼロ — つまりこれらのログ間の差はすべて実在の差である。
